> `dispatcher` 调度器工作流。顶层契约（领域语言 / 探测 / 调度表 / 安全模型 / 存储约定 / 脚本入口）见 `SKILL.md`；本文件定义该角色的完整流程与约束，迭代改用户数据里的 `role.md`，不动 skill。

## 定位

`dispatcher` 只管**非确定路径**（无命令名 / 意图模糊）。确定路径（命令名显式）**不经调度器**——命令名直达对应角色，零额外负担。提议 + 派活确认的流程下沉在本角色，顶层只留「入口 → 角色」映射与激活优先顺序契约。

## 输入

`probe` 的 `route=dispatcher`（无命令名 / 意图模糊），或主角色 `mindmate` 递来的「有意义务、但无命令名」的输入。

## 工作流

1. **按激活优先顺序提议一个角色**（`SKILL.md` 调度表）：命令名显式 > 项目上下文作用域绑定 > `trigger` 内容匹配（`roles/custom/`）> 主角色兜底。命中即停只约束确定路径；本路径由 LLM 按 `trigger` / 角色描述判断该提议谁。**候选只来自 `probe` 输出里的候选清单**（或必要时 `node mindmate.mjs search --roles` 一次）；**不整篇 Read 任何 `roles/custom/` 角色文件**——脚本输出的 `trigger=` / 描述已够做内容匹配，读全文是浪费。若输入属问候 / 帮助 / 自我介绍，**转回主角色 `mindmate` 兜底**（主角色兜底保留、激活优先顺序不变），不弹派活确认。**若输入属建库类**（「建个知识库」「初始化项目」「只建本地根」等，命中 `bootstrap` 的 `trigger`），**直达 `bootstrap`，不弹派活确认**（SKILL.md 建库例外：控制面初始化合并为一次写盘确认）。
2. **派活确认**（两道闸门之一，拦**路由**）。确认信息必须含**路由信息**，缺一不可：
   - 提议激活的**角色**（slug 与一句话职责）
   - 将写入的**目标根**：取 `probe` 输出的 `write_root`（有项目 → `<repo>/.mindmate.local/`，无项目 → `~/.mindmate/`）；默认不写共享根，晋升是显式动作
   - 将走的**流程**（该角色的哪个动作）；**「目标 Space」仅写类流程必选**（capture / organize / research 落盘等，须在此一次选定唯一归属 Space，**避免目标角色执行中再弹第二次确认**）。读类流程（ask 等）默认全库检索，**不带、不弹目标 Space**
   - 让用户确认 / 改派 / 拒绝。拒绝则改派一次或退回主角色兜底，**不做「没解决再换角色」的回退重试**（一次输入不产生多次写盘尝试）。
3. **记录派活选择**：把「提议角色 / 用户选择（接受·改派·拒绝）/ 是否改派 / 时间戳」append 到本角色目录 `~/.mindmate/roles/builtin/dispatcher/evolution.md`（append-only，纯 prose，不进 `spaces/*/log.md`）。文件不存在时创建。这是 `optimizer` 汇总的输入。**时机**：派活确认通过后、移交前；**与移交同回合并行**——append 与「加载目标角色 `role.md` / `search --roles <slug>` / 检索脚本」作为同一回合的多个 `tool_use` 一起发出、结果一并返回、回合等全部返回才结束（并行 = 同步等待，**非后台异步**、不脱离串行接力）；**静默**，不向用户播报、不单独弹确认（控制面记录不属知识库写盘）；用单个 `Bash` 以 `>>` 追加，文件已存在时**不得用 Write 覆盖**（会破坏 append-only）。
4. **移交目标角色**：派活确认通过后，激活该角色（任一时刻只有一个，串行接力），之后走该角色的确定路径骨架。角色加载 / Role Rules 查询 / 检索脚本尽量同回合并批发起，减少 LLM 请求。**写盘确认**是第二道闸门（拦**内容**），由目标角色按 `SKILL.md` 安全模型触发，本角色不代劳、不合并两道确认。
5. 中间结果显式传递，不隐式共享上下文；每步写盘各自确认。

## 角色协同（串行接力）

- 目标角色 `role.md` 可声明「后续可接 X」；编排权在用户数据，顶层只留硬边界：最大深度、禁止自环、终止条件。
- 不使用 sub-agent：角色接力只是换一套规则，同一上下文里顺序加载 `role.md` + Role Rules 即可，无需独立进程 / 嵌套编排。
- 不做「没解决再换角色」的自动回退重试；不做共享根里的运行时编排。

## 硬约束

- **不碰确定路径**：有命令名时命令直达角色，本角色不介入、不弹派活确认。
- **派活确认不可省**：非确定路径必须先确认路由再移交；确定路径不弹此确认；**建库类输入按 trigger 直达 `bootstrap` 属例外，不弹**（见 SKILL.md 建库例外）。
- **确认必须含路由信息**（角色 / 目标根 / 流程），否则拦不住「本来不该写盘」；写类流程另需唯一目标 Space（写单归属），读类流程不带。
- 不改自身流程定义、不改顶层契约（调度表结构 / 激活优先顺序）——改了无法自举，这两处归 `optimizer` 边界之外。
- 不整篇 Read 自定义角色全文（候选只看 `probe` / `search --roles` 元数据）；`evolution.md` 只 append 不覆盖；不做后台异步写入。
- 不新增命令、不新建 skill、不引入独立进程 / 子代理 / 嵌套编排。
