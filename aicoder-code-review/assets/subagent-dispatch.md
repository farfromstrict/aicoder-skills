# 子代理派发与执行规范

本文件是「派发子代理执行单轮审查」的唯一规范：主会话按第二节构造派发，子代理按第三节执行并按第四节返回。**一律派发子代理，禁止直跑**（不分首轮/跟进轮、不分 diff 大小；小 diff 单块派发，大 diff 按功能内聚分块）。子代理不可用时报告阻塞并征询用户，不得由主会话自行审查替代。

## 一、职责划分

| 主会话（有状态） | 子代理（干净上下文） |
|---|---|
| 确定范围与分块 spec（共享归属、邻接摘要定向） | 只读 `tmp/review-prompts/fN.md`（脚本拼好的完整任务） |
| 调 `repo_prep.js` 拼装 prompt、`resolve_lines.js` 解析行号、`render_report.js` 渲染报告 | 逐行审查（五维度 + 分支矩阵推演），返回不带行号的标记文本发现 |
| 对账合并、全局对照（汇总判断，非逐行审查）、正文呈现报告 | 不读 skill 任何文件 |
| 写回 log/lessons（**单一写者**） | 返回结构化发现与增量 |

## 二、派发（主会话执行）

**工具调用合并原则（省 LLM 调用次数）**：config/清单/规约由脚本读，主会话不碰（见步骤2）；能在一次 Bash 完成的侦察/校验合并成一次，不拆多次；脚本产物信任脚本退出码，不重复 `wc -l`/`grep` 校验；同理类的多次 `ls`/`find`/`grep`/`sed` 合并。每次工具调用都会触发一次后续 LLM 调用（带全量上下文），少一次调用 = 少一次累计上报。

1. 分块 spec 由 SKILL.md 工作流步骤1 产出（变更范围已在该步骤就地内联给出），本文件不重复范围获取逻辑。**默认不复核**（不读 review.md）。spec 格式见 `scripts/repo_prep.js` 头部注释：`files`（变更文件全集）、`blocks`（每块 id + files + neighbors 邻接摘要）、`diffArgs`（默认 `-U1`）。**共享文件唯一归属、邻接摘要定向发送**在写 spec 时完成（并行时无法动态调整）。
2. **拼装 prompt（脚本）**：调用 `scripts/repo_prep.js <项目根> <skill根> <spec文件>`。脚本读 config/清单/lessons/diff，**拼装 N 份完整 prompt 到 `tmp/review-prompts/fN.md`**（含红线、执行要点、惯例、邻接摘要、本块 diff、返回格式），主会话不经手正文（token≈0）。脚本 stdout 的 manifest **重定向到文件再 Read**（规避 Bash VT 伪影），据此得到块 id → prompt 路径映射。**不传**未决项/决策明细/回归锚点（复核场景专用）。
3. **一次性并行派发（先核对块数）**：**派发前逐一核对 manifest 的每一个块 id（f1…fN）都有对应 Agent 调用，禁止漏派**——曾发生"spec 写了 3 块只派 2 个"（新增未跟踪文件那块被漏）。一条消息对 N 个块同时发 N 个子代理调用，每个只传"用 Read 读取 `tmp/review-prompts/fN.md` 并严格遵守其中任务"。墙钟从 `sum(块)` 压到 `max(块)`。子代理发现**不带行号**、用轻量标记文本（`### [级别]`/`REF:`/`CODE:`/`WHY:`/`FIX:`）。接收后主会话对账合并（同文件同语义）。

**分批协议**（diff 超过约 500 行时适用；≤500 行单块派发，不分功能）：

- **分批判据——按功能内聚，不按目录模块**：多处相互独立的修改 → 按功能块拆分，目标每块 300–600 行，**上限 4 块**（超过则合并功能相关性最高的相邻块；按功能拆而非按检查维度拆——维度拆分会让同一 diff 被读 N 遍并重复报）。横切功能（一个特性贯穿多层，如 iam+admin+common+DDL）→ **不拆**，单次大派发（接受注意力稀释，换跨模块视野——不对称/契约漂移类发现依赖跨模块视野）
- **≤500 行不拆**：总 diff ≤ 500 行一律单块派发，不做功能拆分（拆分带来的冷启动开销 > 收益）
- **共享文件唯一归属**：派发前主会话轻量侦察（`git diff --stat` 按目录聚合），被多个功能块触碰的共享文件（common/core）只归属一个派发，其他派发的 prompt 注明"该文件由 F-x 覆盖，勿重复报"
- **邻接摘要（定向发送）**：派发前先判断块间交互关系（共享文件归属、接口调用、同根因疑似）→ **只给本块附与其有交互关系的块**的接口签名与关键事实摘要（一两百字），无交互关系的块摘要不发（3 块全量广播会浪费约 1/3 摘要 token）。供跨模块对照（不对称/重复实现类发现依赖它），不附对方代码全文
- **合并对账**：多次派发的发现由主会话按"同文件同语义"对账合并，同根因合并为一条并保留全部位置
- **全局收尾对照**：合并后主会话做一次跨模块专项检查（接口一致性 / 重复实现 / 依赖方向），**由主会话直接基于各块发现 + 接口签名完成，不重读代码、不追加派发**（再派发是一次冷启动，费时费 token，收益不足）。**「对照」是基于已有发现的汇总判断，不是逐行审查，不违反「禁止直跑」**——禁止直跑针对的是"由主会话替代子代理做逐行审查"
- **编号**：各块返回 F1..Fn（块内编号），主会话合并后统一重编全局编号

**无直跑例外**：任何轮次、任何 diff 大小都必须派发子代理（小 diff 单块派发、大 diff 分块），主会话不得自行审查替代。

## 三、执行规范（子代理执行）

- **按 prompt 文件执行**：子代理**只读** `tmp/review-prompts/fN.md`，**不读** skill 任何文件。该文件由 `repo_prep.js` 拼装，已含：按 config 开关筛选的清单/规约原文、惯例缓存、本块 diff、任务与返回格式。config 的维度开关（`review.*`，`false` 则该维度清单不纳入、不报；正确性不可关）、`exclude`（命中文件不审）、规约优先级（项目级 > 用户级 > 内置的清单/规约取舍）均由脚本处理，子代理无需关心；按语言/框架选清单：Java/Spring → `java-checklist.md`；Vue → `vue-checklist.md`；JS/TS → `js-ts-checklist.md`（Vue+TS 两份）；security 开 → `security-checklist.md`；ai-pitfalls 开 → `ai-code-pitfalls.md`（默认开）
- **高层审查**：模块职责、架构一致性、重复造轮子（先搜索项目已有实现）。审查 AI 生成代码时先做**项目惯例归纳**：读同包/同层的存量同类文件，提取惯例清单（基类与统一封装、错误处理模式、命名/日志/校验/数据访问惯例）。主会话内联的共享片段（lessons 惯例缓存+决策口径）直接复用、不重读存量文件；新归纳的惯例记入增量。惯例以存量代码为准，不以通用最佳实践为准（检查点见 ai-code-pitfalls.md 第 4 节）
- **逐行审查**：正确性、安全、性能、可维护性、AI 专项五个维度（被配置关闭的维度除外），对照清单逐项过。对构成分支矩阵的代码段强制推演：同一段逻辑内存在 ≥2 个相互作用的条件变量（try/catch 标志位、boolean 返回值分支、集合空/非空、早退 continue/break、异常 catch）——枚举条件组合的全部分支路径，对每条路径核对两问：①重复？该组合下关键动作（副作用、状态变更、日志）是否被执行多次，或该路径的处理与相邻路径重叠（"分支内一次 + 兜底一次"的防御式双写、"保证覆盖"式写法）；②完备？该组合是否有明确定义的处理——包括"无操作"：若一条路径什么都不做，必须能确认是有意设计而非复制分支时遗漏（"全空/全等/无变化/都失败"类组合是 AI 最常漏的格子）。仅当存在对账/统计/分类结构时附加第三问：每条路径是否归入且只归入一个已知类别（口径漂移）。路径较多时可优先审查含写操作或状态变更的路径
- **分级边界**：🟡 严重仅限会导致生产环境行为异常的逻辑错误（空指针/非法状态、并发竞态、数据完整性破坏、越权/注入等安全缺陷、功能不可用且无兜底）；代码风格、命名、注释、测试完备性缺失、纯实现偏好一律 🟢 一般或 💡 轻微；🔴 阻断仅限合入即引发生产事故/数据损坏/安全事件且无兜底；项目规约文件（rules/*.md）可重定义边界（重定义后以规约为准）
- **历史项核实（复核场景专用，默认不执行）**：本 skill 默认审查**不读 review.md、不做任何历史项核实/决策复核/回归检测**。仅当用户明确要求"复审/复查/再审一遍/核实遗留项"等复核意图时，另起复核流程，届时由主会话提供历史包（未决项、决策明细行、🔴🟡 已修复锚点）后执行：未决项逐条回代码核实——已修标"已修复"、仍在标"遗留 Rx-y"（≥3 轮加"第 N 次提醒"徽标）、决策不改不报告；**决策复核**前提变化时重验（仍成立抑制并标"第 N 轮复核"、不成立则解除抑制报"推翻 Rx-y"）；**回归检测**对照 🔴🟡 已修复锚点，修复不存在则报"回归（Rx-y，第 N 轮复现）"。默认审查中禁止凭 log 转抄任何历史结论
- **Diff 优先读法**：diff 内容（或临时文件）由 prompt 提供，直接阅读 hunk，变更文件不主动通读全文——仅当 hunk 语义不足（引用了未包含的符号、上下文断裂）时定点补读；不假定可执行 git 命令
- **验证定位**：每条发现打开文件确认逐字代码与可定位符号；行号**不在此步解析**（由主会话渲染前统一 grep 解析）；找不到确凿位置的疑似问题降级为提问式反馈
- **输出前逐块自检**：每条发现的逐字代码必须真实、与源文件一致，可定位符号须唯一可 grep

## 四、返回契约（子代理 → 主会话）

**输出为轻量标记文本**（与 `scripts/render_report.js` 解析格式一致；不使用 JSON，不带行号）：

```
## 总体评价
<1-2 段整体质量结论 + 最需关注方向>
## 问题
### [💡] 标题（级别用 🔴/🟡/🟢/💡）
REF: src/a.vue:76
CODE: <逐字代码，可多行，直到下一个字段前缀>
WHY: <说明与影响>
FIX: <修复建议；💡 可省略>
### [🟢] 另一个标题
REF: ...
CODE: ...
WHY: ...
FIX: ...
## 结论
Comment
```

- `REF:` 带相对路径 + 起始行（行号由脚本批量解析后校正）；无确定行号时可只给路径。
- 空字段不写；无问题的级别不输出 `###` 块。
- 复核场景专用节（决策复核、历史项核实）见 `review-state-recheck.md`，默认不输出。

主会话收到后：合并各块标记文本（同文件同语义对账）→ 把 `REF`/`CODE` 的可定位信息写成 JSON 交 `scripts/resolve_lines.js` 批量解析行号 → 校正 REF 后交 `scripts/render_report.js` 生成 markdown → 读报告原文**原样正文输出**。抽样核对：输出前抽查 1-2 条逐字代码与文件一致，不一致整批退回重验。默认不写"修复确认"（复核场景专用）。
