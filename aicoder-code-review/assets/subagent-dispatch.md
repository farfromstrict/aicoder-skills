# 子代理派发与执行规范

本文件是「派发子代理执行单轮审查」的唯一规范：主会话按第二节构造派发，子代理按第三节执行并按第四节返回。**一律派发子代理，禁止直跑**（不分首轮/跟进轮、不分 diff 大小；小 diff 单块派发，大 diff 按功能内聚分块）。子代理不可用时报告阻塞并征询用户，不得由主会话自行审查替代。

## 一、职责划分

| 主会话（有状态） | 子代理（干净上下文） |
|---|---|
| 读 config/清单提炼执行要点、确定范围、物化 diff | 只读本 prompt 内联的执行规范与要点（不读 skill 任何文件） |
| 写共享片段文件（惯例缓存+决策口径）、准备各块邻接摘要 | 高层审查（惯例归纳，对照内联的共享片段） |
| grep 统一解析行号、渲染报告（report-generation.md） | 逐行审查（五维度 + 分支矩阵推演），返回不带行号的发现 |
| 写回 log/lessons（**单一写者**） | 返回结构化发现与增量 |

## 二、派发（主会话执行）

1. 确定本轮范围（`git diff` 或用户指定）。**默认不复核**：不读 `review.md`（不判模式、不取未决项/决策明细/回归锚点）。读一次 lessons 的「项目惯例缓存」「用户决策口径」两段，**写成一份共享片段文件**（如 `tmp/review-shared-context.md`），供各块 prompt 引用同一份；各块只附本块邻接摘要，不再重复内联惯例全文
2. 主会话读一次 `.aicoder/code-review/config.yaml` 与按开关选中的清单/规约，**提炼成「执行要点」**（启用的维度、清单关键检查点、适用规约条）——这是要内联进 prompt 的内容，**子代理不再各自读清单文件**。构造派发 prompt，必须包含：
   - **执行要点已内联**：本 prompt 的"执行规范"即完整依据（含内联的执行要点），子代理**无需读取 skill 任何文件**（SKILL.md/review-state.md/清单/规约均不读）；项目 config 取舍由主会话在内联要点中说明
   - 本轮范围文件清单（**不标注首轮/跟进轮，默认不复核**）；**diff 由主会话物化**——派发前主会话执行 `git diff -U1`（**默认用 `-U1` 压缩上下文，比 `-U3` 省约 30% 输入 token**；语义不足时再对该文件补读全文），**不假定子代理有 shell 工具**；超长时按降级链处理：①按文件拆分——先 `git diff --stat` 出清单，再逐文件 `git diff -U1 -- <file>`；②单文件仍超长用 `-U0` 进一步压缩上下文行；③超大 diff 写入临时文件并告知子代理路径，由其分页读取；④最后手段才是通读变更文件全文，且必须先保留 `--stat` 文件清单与变更行号清单作为审查锚点
   - **共享片段**：给共享上下文文件路径（惯例缓存+决策口径，各块共用一份）+ 本块邻接摘要（一两百字，供跨块对照）。**不传**未决项、决策明细行、🔴🟡 已修复锚点——这些属复核场景，默认不复核（见「复核场景」节）
   - **红线**：纯静态分析，禁止编译/测试/写操作；每条发现给**逐字代码行 + 相对路径 + 可定位文案/符号，不带行号**（行号由主会话在渲染前用 grep 统一解析填入）；用户已声明非 AI 代码时跳过 ai-code-pitfalls
3. **一次性并行派发所有块**：在一条消息里对 N 个功能块同时发 N 个子代理调用（互不依赖，全部前台等待），墙钟时间从 `sum(块)` 压到 `max(块)`。前置条件：各块的邻接摘要、共享文件归属必须在派发前（第 1、2 步）全部算好——并行时无法根据某块结果动态调整后续块。并行不省 token（每块基础开销固定），只省时间

**分批协议**（diff 超过约 500 行时适用；≤500 行单块派发，不分功能）：

- **分批判据——按功能内聚，不按目录模块**：多处相互独立的修改 → 按功能块拆分，目标每块 300–600 行，**上限 4 块**（超过则合并功能相关性最高的相邻块；按功能拆而非按检查维度拆——维度拆分会让同一 diff 被读 N 遍并重复报）。横切功能（一个特性贯穿多层，如 iam+admin+common+DDL）→ **不拆**，单次大派发（接受注意力稀释，换跨模块视野——不对称/契约漂移类发现依赖跨模块视野）
- **≤500 行不拆**：总 diff ≤ 500 行一律单块派发，不做功能拆分（拆分带来的冷启动开销 > 收益）
- **共享文件唯一归属**：派发前主会话轻量侦察（`git diff --stat` 按目录聚合），被多个功能块触碰的共享文件（common/core）只归属一个派发，其他派发的 prompt 注明"该文件由 F-x 覆盖，勿重复报"
- **邻接摘要**：每个派发的 prompt 附其他功能块的接口签名与关键事实摘要（一两百字），供跨模块对照（不对称/重复实现类发现依赖它），不附对方代码全文
- **合并对账**：多次派发的发现由主会话按"同文件同语义"对账合并，同根因合并为一条并保留全部位置
- **全局收尾对照**：合并后主会话做一次跨模块专项检查（接口一致性 / 重复实现 / 依赖方向），**由主会话直接基于各块发现 + 接口签名完成，不重读代码、不追加派发**（再派发是一次冷启动，费时费 token，收益不足）。**「对照」是基于已有发现的汇总判断，不是逐行审查，不违反「禁止直跑」**——禁止直跑针对的是"由主会话替代子代理做逐行审查"
- **编号**：各块返回 F1..Fn（块内编号），主会话合并后统一重编全局编号

**无直跑例外**：任何轮次、任何 diff 大小都必须派发子代理（小 diff 单块派发、大 diff 分块），主会话不得自行审查替代。

## 三、执行规范（子代理执行）

- **按主会话内联的执行要点执行**：子代理**不读** skill 任何文件（config/清单/规约/SKILL.md/review-state.md 已由主会话读取并提炼为内联要点）。项目 config 的维度开关与 `exclude`、适用清单的检查点、项目级 > 用户级 > 内置规约的取舍，均由主会话按下列规则提炼后写进 prompt：config 读项目根 `.aicoder/code-review/config.yaml`（不存在全默认、格式错误警告后默认继续），`review` 维度 `false` 则跳过该维度（清单**不内联**、该维度不报；正确性不可关），`exclude` 命中文件不审；规约优先级 项目级 `.aicoder/code-review/rules/*.md` > 用户级 skill `references/rules/*.md` > 内置清单（同义冲突项目覆盖用户，`javascript`/`typescript` 同一族）；按语言/框架选清单：Java/Spring → `java-checklist.md`；Vue → `vue-checklist.md`；JS/TS → `js-ts-checklist.md`（Vue+TS 两份都内联）；security 开 → `security-checklist.md`；ai-pitfalls 开 → `ai-code-pitfalls.md`（用户声明非 AI 代码时跳过，默认开）
- **高层审查**：模块职责、架构一致性、重复造轮子（先搜索项目已有实现）。审查 AI 生成代码时先做**项目惯例归纳**：读同包/同层的存量同类文件，提取惯例清单（基类与统一封装、错误处理模式、命名/日志/校验/数据访问惯例）。主会话内联的共享片段（lessons 惯例缓存+决策口径）直接复用、不重读存量文件；新归纳的惯例记入增量。惯例以存量代码为准，不以通用最佳实践为准（检查点见 ai-code-pitfalls.md 第 4 节）
- **逐行审查**：正确性、安全、性能、可维护性、AI 专项五个维度（被配置关闭的维度除外），对照清单逐项过。对构成分支矩阵的代码段强制推演：同一段逻辑内存在 ≥2 个相互作用的条件变量（try/catch 标志位、boolean 返回值分支、集合空/非空、早退 continue/break、异常 catch）——枚举条件组合的全部分支路径，对每条路径核对两问：①重复？该组合下关键动作（副作用、状态变更、日志）是否被执行多次，或该路径的处理与相邻路径重叠（"分支内一次 + 兜底一次"的防御式双写、"保证覆盖"式写法）；②完备？该组合是否有明确定义的处理——包括"无操作"：若一条路径什么都不做，必须能确认是有意设计而非复制分支时遗漏（"全空/全等/无变化/都失败"类组合是 AI 最常漏的格子）。仅当存在对账/统计/分类结构时附加第三问：每条路径是否归入且只归入一个已知类别（口径漂移）。路径较多时可优先审查含写操作或状态变更的路径
- **分级边界**：🟡 严重仅限会导致生产环境行为异常的逻辑错误（空指针/非法状态、并发竞态、数据完整性破坏、越权/注入等安全缺陷、功能不可用且无兜底）；代码风格、命名、注释、测试完备性缺失、纯实现偏好一律 🟢 一般或 💡 轻微；🔴 阻断仅限合入即引发生产事故/数据损坏/安全事件且无兜底；项目规约文件（rules/*.md）可重定义边界（重定义后以规约为准）
- **历史项核实（复核场景专用，默认不执行）**：本 skill 默认审查**不读 review.md、不做任何历史项核实/决策复核/回归检测**。仅当用户明确要求"复审/复查/再审一遍/核实遗留项"等复核意图时，另起复核流程，届时由主会话提供历史包（未决项、决策明细行、🔴🟡 已修复锚点）后执行：未决项逐条回代码核实——已修标"已修复"、仍在标"遗留 Rx-y"（≥3 轮加"第 N 次提醒"徽标）、决策不改不报告；**决策复核**前提变化时重验（仍成立抑制并标"第 N 轮复核"、不成立则解除抑制报"推翻 Rx-y"）；**回归检测**对照 🔴🟡 已修复锚点，修复不存在则报"回归（Rx-y，第 N 轮复现）"。默认审查中禁止凭 log 转抄任何历史结论
- **Diff 优先读法**：diff 内容（或临时文件）由 prompt 提供，直接阅读 hunk，变更文件不主动通读全文——仅当 hunk 语义不足（引用了未包含的符号、上下文断裂）时定点补读；不假定可执行 git 命令
- **验证定位**：每条发现打开文件确认逐字代码与可定位符号；行号**不在此步解析**（由主会话渲染前统一 grep 解析）；找不到确凿位置的疑似问题降级为提问式反馈
- **输出前逐块自检**：每条发现的逐字代码必须真实、与源文件一致，可定位符号须唯一可 grep

## 四、返回契约（子代理 → 主会话）

```markdown
## 状态回执
- 分块：<F-x / 单块>；按内联执行要点完成审查（默认不判模式、不读历史）
- 实际审查文件清单：<相对路径列表>

## 发现
### F1 [🔴 阻断|🟡 严重|🟢 一般|💡 轻微] 标题
- 引用：相对路径（**不带行号**，行号由主会话用 grep 统一解析后填入引用块）
- 代码（逐字）：<真实代码行，可含 1-2 行上下文>
- 可定位符号/文案：<变量名/类名/关键文案，供主会话 grep 定位>
- 说明与影响：<...>
- 修复建议：<🔴/🟡/🟢 必填；涉及代码给 ❌ Bad / ✅ Good 对照>

## 决策复核（复核场景专用）
- R<x>-y 第 N 轮复核：<结论>（前提变化：<...>）→ 仍成立 | 推翻

## 历史项核实（复核场景专用）
- <逐条核实结论>

## 惯例增量
- <新归纳的项目惯例，供 lessons 项目惯例缓存>

## 模式计数增量
- <模式名> +1（如适用）

## 提问式条目（不确定、需用户澄清）
- <...>
```

**空节省略**：上述各节无内容时**整节不输出**（包括"状态回执"之外的任何节），不写"无"/"N/A"占位；仅保留有实质内容的节。

主会话收到后：合并各块发现（同文件同语义对账）；**用 grep 按"可定位符号/文案"统一解析每条发现的真实行号**，填入 `assets/report-generation.md` 要求的可点击引用块；按 `assets/report-generation.md` 渲染报告（发现转 `### N.` 问题条目）；抽样核对：渲染前抽查 1-2 条发现的逐字代码与文件一致，不一致整批退回重验。默认不写"修复确认"（复核场景专用）。
