# 报告生成模块

**报告排版由 `scripts/render_report.js` 完成**——引用块语法、连续编号、分级分节、速览表行数自检等格式规则已内置脚本，主会话不再逐条遵守格式细则。本文件只留：判定口径 + 脚本接口。

## 脚本接口

1. `scripts/resolve_lines.js <项目根> <findings.json>` — 批量解析行号。findings 为 `[{path, locate}]`，输出 `[{path, locate, lines}]`。locate 为可定位符号/文案子串；找不到则 lines 空（降级提问式或定点补读）。
2. `scripts/render_report.js <标记文本> [--out <文件>]` — 套模板生成 markdown 报告，stdout 或写文件。**脚本 stdout 须重定向到文件再 Read**（规避 Bash VT 伪影）。

标记文本格式（子代理输出）：

```
## 总体评价
<文字>
## 问题
### [💡] 标题
REF: src/a.vue:76
CODE: <逐字代码>
WHY: <说明与影响>
FIX: <修复建议>
## 结论
Comment
```

级别用 🔴/🟡/🟢/💡；空字段不写；多个问题重复 `### [级别]` 块。

## 判定口径（LLM 负责，脚本不做）

- **审查结论四选一**：任一 🔴 → 🔄 Request Changes；仅 🟡/🟢/💡 → 💬 Comment；架构方向分歧 → 🔍 Needs Discussion；无问题 → ✅ Approve。写入标记文本 `## 结论`。
- **分级边界**：🟡 严重仅限生产行为异常的逻辑错误（空指针/非法状态/竞态/数据完整性/越权注入/功能不可用无兜底）；风格/命名/注释/测试缺失/实现偏好一律 🟢 或 💡；🔴 阻断仅合入即生产事故无兜底。项目 `rules/*.md` 可重定义，以规约为准。
- **总体评价**：1-2 段整体质量结论 + 最需关注方向。默认不写"修复确认"（复核场景才写）。
- **修复建议**：每条 🔴/🟡/🟢 必给简要改法；💡 本身即建议，无需再附。

## 正文呈现（硬约束）

报告**必须以正文呈现**——主会话读 `render_report.js` 产物后原样输出，不得只给"结论 + 文件链接"。报告正文的输出 token 省不掉，脚本只省格式规则与返工。

复核场景的轮次信息行、修复确认：`references/review-state-recheck.md`（默认不读）。
