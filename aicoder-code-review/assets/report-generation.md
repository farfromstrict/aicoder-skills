# 报告生成模块

**写报告前必须完整读取本文件。**本文件是报告输出格式的唯一规范，含核心格式、报告骨架、硬性要求与常见错误。

## 一、核心格式：可点击引用代码块

把 `起始行:结束行:相对路径` 写在**代码块标注行**——与三个反引号**同一行**（紧跟反引号之后、替代语言名，反引号与路径之间**禁止换行**），代码内容从下一行开始。**对照示例（左错右对，必须按 ✅ 的写法输出）：**

❌ Bad（标注行写了 `code`，路径成了内容第一行——IDE 只显示普通代码块，不可点击）：

````markdown
```code
163:165:fuxi-auth-iam/src/main/java/com/cicc/ctie/fuxi/auth/iam/service/impl/SessionServiceImpl.java
if (null != extInfo) {
```
````

✅ Good（`起始行:结束行:路径` 在标注行上，紧跟三个反引号，路径后无任何其他字符）：

````markdown
```163:165:fuxi-auth-iam/src/main/java/com/cicc/ctie/fuxi/auth/iam/service/impl/SessionServiceImpl.java
if (null != extInfo) {
    fuxiUser.setEmployeeId(String.valueOf(extInfo.get(CommonConst.TENANT_USER_EXT_EMP_ID)));
}
```
````

IDE 会把 ✅ 的块渲染为带 `SessionServiceImpl.java L163-L165` 标签的可点击代码块，点击直接打开文件对应行。

**三个禁止**：
1. 禁止标注行写任何语言名或 `code` 字样（` ```java `、` ```code ` 都会让 IDE 把它当普通代码块，失去可点击标签）——标注行只能以 `数字:数字:路径` 开头
2. 禁止把 `行号:行号:路径` 写进代码内容里（作为第一行文本）——包括"标注写在反引号的下一行"这一变体：那会被当成纯文本内容，块失去可点击标签，IDE 只显示 `code` 兜底标签
3. 禁止用行内 `` `path:line` `` 表达文件行号——所有位置引用一律用引用代码块，单行写 `87:87:相对路径`

行内反引号只用于代码符号（方法名、变量名、常量名）。

## 二、报告骨架

`---` 分割线一个都不能少；问题编号手写进标题文字（`### 1.`、`### 2.`……跨分节连续），不依赖 markdown 自动编号。

````markdown
# 代码审查：[变更主题/文件范围]

[轮次信息行在复核场景才写：`第 N 轮（接续 <日期·主题>，携遗留 M 项）`。默认审查不判模式、不读历史，省略本行]

---

## 总体评价

[1-2 段：整体质量结论 + 最需要关注的问题方向。默认审查不写"修复确认"——不读历史、不核实遗留项。仅复核场景在总评先写修复确认：上轮 M 项已修复 X（列编号）/遗留 Y/决策不改 Z]

---

## 🔴 阻断

### 1. [问题标题]

[引用代码块]

[问题说明与影响；修复建议（每条必给，见硬性要求 10）；修复涉及代码时附 ❌ Bad / ✅ Good 对照]

### 2. [问题标题]

...

---

## 🟡 严重

### 3. [问题标题]

...

---

## 🟢 一般

### 4. [小改进 + 单行引用代码块]

---

## 💡 轻微

### 5. [备选方案 + 单行引用代码块]

---

## 📚 说明（可选，无则不设本节）

### 6. [教育性说明，无需行动]

---

## 审查结论

**[结论]** —— [一句话理由]

[有问题时附"问题速览"表（全部问题进表）；无任何问题则不设]

**问题速览**（直接放正文，markdown 表格正常渲染）

| 编号 | 问题 |
|------|------|
| 🔴 1 · `SessionServiceImpl.java` | `String.valueOf` 掩盖 null，产生 "null" 字符串 |
````

## 三、硬性要求

1. **分割线分节**：主标题、总体评价、每个问题级别分节、审查结论之间用 `---` 隔开
2. **红绿灯大标题**：`## 🔴 阻断` / `## 🟡 严重` / `## 🟢 一般` / `## 💡 轻微`，按严重度从高到低；某级别无问题则不设该节。分级显示名固定为：🔴 阻断 / 🟡 严重 / 🟢 一般 / 💡 轻微 / 📚 说明（对应配置 `level` 机器值 severe / important / normal / minor；📚 说明无规则级别，报告只出现中文名，不出现英文标签）
3. **问题标题用标题样式**：写成 `### N. 标题`（比分节 `##` 小一级），不用普通加粗文本
4. **全报告连续序号**：编号手写进标题文字，跨分节连续（🔴 的 2 接 🟡 的 3），禁止每节从 1 开始
5. **不生成 praise**：不设亮点区，不做优点分析，报告只包含问题与结论
6. **所有**文件行号引用（含 🟢/💡/正文说明）都用引用代码块，标注行格式 `起始行:结束行:相对工作区根路径`，路径相对工作区根目录。**行号由主会话用 grep 按子代理提供的"可定位符号/文案"统一解析后填入**（子代理返回不带行号），不得照抄子代理给的行号
7. **问题速览表**：仅出现在审查结论之后，**列出全部问题（🔴/🟡/🟢/💡 全部进表）**；两列带表头（`编号` / `问题`），第一列为红绿灯、序号、文件名（如 `🔴 1 · 文件名`，不带行号，定位由正文可点击代码块承担）；表格直接放正文正常渲染，不用围栏代码块包裹，表格外禁止附加任何注解；**自检红线：表内行数必须恰好等于全部问题条数（🔴+🟡+🟢+💡），漏一行即违规**；此表是全报告唯一允许的表格
8. 语言与用户一致（默认中文）
9. 不确定的问题用提问式（"如果 `items` 为空会怎样？"），并降级为 💡 或 🟡
10. 语气建议式而非命令式；**每条 🔴/🟡/🟢 问题必须附清晰简要的修复建议**：一两句话说明改法与方向，只报问题不给建议视为报告不完整；修复涉及代码时给出 ❌ Bad / ✅ Good 对照代码（无可对照的"坏写法"时给单段 ✅ Good 即可）；建议代码必须基于问题引用处的真实代码改写，禁止编造上下文；依赖外部决策、确实无法给出建议时须说明原因并转为提问式（💡 本身即为建议，无需再附改法）
11. 问题区不用表格（速览表除外）
12. **输出前逐块自检**：每个引用代码块的反引号行必须是 ` ```数字:数字:相对路径 `（标注与反引号同行）；任何块的内容第一行出现 `数字:数字:路径` 即为违规，立即重写该块
13. **轮次上下文（复核场景专用，默认不执行）**：默认审查不判模式、不读历史、不写修复确认，无轮次信息行。仅复核场景才加轮次信息行、总评先写修复确认（已修复项列编号）；已决策不改的问题在该场景下禁止再生成问题条目
14. **分级判定边界（重定义 Important）**：🟡 严重仅限**会导致生产环境行为异常的逻辑错误**——空指针/非法状态、并发竞态、数据完整性破坏、越权/注入等安全缺陷、功能不可用且无兜底；代码风格、命名、注释、测试完备性缺失、纯实现偏好一律 🟢 一般或 💡 轻微。🔴 阻断仅限**合入即引发生产事故/数据损坏/安全事件且无兜底**的问题。项目可在规约文件（rules/*.md）中重定义边界，重定义后以规约为准

## 四、常见错误

| 错误 | 纠正 |
|------|------|
| 没读本文件就写报告 | 写报告前必须完整读取本文件 |
| 引用代码块标注行写了语言名或 `code` | 标注行只能是 `起:止:路径`，任何其他字符都会失去可点击标签 |
| 把 `起:止:路径` 写进代码内容当第一行 | 那是纯文本不可点击；路径只能出现在标注行 |
| 标注写在反引号行的下一行（路径成了内容第一行） | 标注必须与三个反引号**同一行**替代语言名，下一行直接是代码内容 |
| 速览表遗漏 🟢/💡，或行数与问题总数不符 | 红线：速览表行数必须等于全部问题条数（🔴+🟡+🟢+💡），漏一行就补 |
| 速览表用围栏代码块包裹，或表格外附注解 | 速览表直接放正文正常渲染，不用围栏代码块；表格外禁止任何注解 |
