# 复核场景专用规范

本文件承载**复核场景专用**的状态规则。默认审查不读本文件——仅当用户明确要求"复审/复查/再审一遍/核实遗留项"等复核意图时才启用。

配套主文件 `review-state.md`（写回必需规则，每轮写回都会读）。

## 一、模式判定（轮首：首轮 / 跟进 / 接续编号）

- **核心不变量：模式只决定历史项处理与报告呈现，不决定审查范围与深度**——跟进轮同样是完整审查（配置/清单/惯例归纳/逐行审查全量执行，默认由干净上下文的子代理执行，照常找新问题），历史项核实只是叠加动作，绝不退化为只复核已修点
- 状态文件不存在 → 首轮
- 存在 → 主判据 = **条目主题 + 分支与本轮请求/变更的一致性**（主题规则见 `review-state.md` 第二节）；未决/决策行的文件路径为辅助弱信号（同文件不同变更也会交集，不作主键）
- 判定结果与依据写入报告标题行：`第 2 轮（接续 11-04 add-user-token，携遗留 2 项）` 或 `首轮（log 中有同文件历史条目 11-04，如属同一变更请告知接续）`
- 错判不损坏数据，三道防线：判定依据显式声明（一句话可纠）→ 轮首错判由写回兜底 → **写回前必须重读最新 log 并与现有条目对账合并**（同文件同语义 → 接续编号/合并，禁止新开重复条目）

## 二、决策不改的复核与推翻

再次遇到同文件同语义疑似问题 → 默认静默抑制；决策前提随代码演进变化、复核后**仍成立** → 抑制并在决策行理由追加「第 N 轮复核：<结论>」（只保留最近一次标记）；复核后**不再成立** → **推翻**：抑制解除，作为正常问题报告（注明"推翻 R<x>-y 决策"），原决策行标记「已推翻(第 N 轮，见 Rx-z)」。

## 三、已修复项的回归检测

🔴🟡 已修复行 = **回归检测锚点**（存根与活跃条目中的明细行），随历史包进入每轮核实；当前代码同文件同语义**修复已不存在** → 回归：作为正常问题报告，标题标注「回归（Rx-y，第 N 轮已修复后复现）」，级别维持原级别；台账原行改回「未决（第 M 轮回归）」。
