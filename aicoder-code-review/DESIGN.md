# DESIGN — 设计与决策记录

> **本文件是设计与决策记录，非运行时规范。**运行时行为以 `SKILL.md`、`references/review-state.md`、`assets/report-generation.md`、`assets/subagent-dispatch.md` 为准。本文件解释"为什么这样设计"，供维护者与承担 skill 演进任务的会话使用，**不进入运行时加载链**。

## 1. 定位与使用约束

- 读者：skill 维护者 + 承担 skill 演进任务的 agent 会话
- 内容：架构取舍、设计边界、分级词表调研、决策时间线、演进注意
- 使用约束：改 skill 前先读本文件，避免重新讨论已裁决的问题；新增设计决策时在「决策记录」补一行（带日期）
- **README 与 DESIGN 是人类文档，运行时链禁止引用**：SKILL 精简的合法手段只有去重与压缩，运行时知识不得外移出 skill 文件（外移 = 运行时丢失）

## 2. 多轮架构：设计取舍

### 2.1 分层模型与存储

四层：变更级（`review.md` 台账）→ 项目级（`lessons.md` 孵化 + `config.yaml` 行为开关 + `rules/*.md` 项目规约）→ 用户级（`references/rules/*.md`）→ skill 级（内置清单）。

关键取舍：
- **lessons 物理在项目级、语义是孵化层**：同一 AI 毛病跨项目各出现 1 次都够不着晋升阈值，靠"用户在任一项目手动晋升到用户级 rules"覆盖——为此不设"用户级孵化层"（第四存储不值得）
- **config.yaml 与 rules/*.md 职责分离**：config 只放行为开关（维度/exclude），知识全部进 rules/*.md——"怎么审"与"什么重要"分离；**类别文件制**（一个类别一个文件）让晋升变为"追加分节"，规避 yaml 列表内联编辑的并行覆盖事故
- **状态文件整体随 `.aicoder/` gitignore（项目本地定位）**：团队共享叙事移除（实测 `.aicoder` 整目录被忽略，共享叙事名存实亡）；团队规约走代码库文档/openspec
- **不设"范围行"**：30+ 文件全清单判别力弱（同文件不同变更照样交集）且每轮 ~1k token，实测第 4 轮存根无范围行、第 5 轮仍靠主题+决策行正确接续——匹配主键定为**条目主题+分支**

### 2.2 台账行生命周期：决策行与已修复行不对称保留

- **决策不改行保留明细**（文件路径 + 复核标记）：支撑静默抑制与「第 N 轮复核 / 推翻」三分支
- **🔴🟡 已修复行保留明细**（🟢💡 压缩计数）：作回归检测锚点——回归发现标注「回归（Rx-y，第 N 轮已修复后复现）」，级别维持原级别（不自动升级原则）
- 取舍依据：台账保留"未来还要被对照的事实"，压缩"纯粹的历史"；成本 ≈ +500 token/轮，三重边界（行数线性增长、log 200 行软上限、30 天老化）
- 实战教训（两次）：存根化曾把决策明细行/已修复明细压成计数，导致已决策问题被重复报告、回归检测失效——均从会话历史原始 JSON 恢复；"写回前强制重读最新 log"由此入规范

### 2.3 子代理架构：读取集最小化

- 单轮分析默认派发干净上下文子代理。实证：同会话连跑时第 2 轮（`再次review`）零新发现 = 旧文案 + **上下文锚定**复合——锚定只有干净上下文能治，文案治不了；主上下文从 O(累积) 变 O(单轮)，多轮不膨胀
- 子代理读取集：prompt 内联执行规范 + config + 清单 + 代码——**不读 SKILL.md / review-state.md / lessons.md**（主会话职责，或由主会话摘录进历史包）。每轮固定开销省 ~3-4k
- **diff 由主会话物化进 prompt**：不假定子代理有 shell 工具（code-explorer 为只读探索工具集）；截断降级链在物化阶段执行
- 主会话职责：模式判定、派发、渲染报告、台账写回（**单一写者**）
- 派发类型指定 code-explorer：只读工具集天然满足纯静态红线；审查方法论由 prompt 内执行规范驱动，子代理人格影响是次要项

### 2.4 分批协议：功能内聚，不按目录

- 判据：diff > 400 行**且**按功能边界可自然切开才拆；横切功能（一个特性贯穿多层）**不拆**，单次大派发换跨模块视野——不对称/契约漂移类发现依赖跨模块视野（R3-1"与 iam 不对称"即跨模块对照产物）
- 四道防线：共享文件唯一归属 / 邻接摘要（接口签名供跨模块对照）/ 主会话合并对账 / 全局收尾对照
- 风险承认：拆分有跨模块遗漏与共性双报两类风险，四道防线即为覆盖它们而设

## 3. 分级词表调研结论（2026-11-04）

| 生态 | 设计 |
|---|---|
| Anthropic Claude Code 官方托管 review | 3 级：🔴 Important（合并前修复）/ 🟡 Nit（不阻塞）/ 🟣 Pre-existing（非本 PR 引入）；内部键 `nit/normal/pre_existing`——**显示名与机器键分离是官方常态**（显示 Important ↔ 键 normal）；附折叠 "Why this was flagged" 推理区块；审查永不批准/阻止 PR |
| code-review-skill（本环境） | 6 标签：blocking/important/nit/suggestion/learning/praise——与本项目原词表同源 |
| CodeRabbit | 双轴：type（nitpick/suggestion 是类型标签）× merge-blocking |
| Qodo（PR-Agent） | 行动级（Action required / Review recommended / Advisory）映射 CRITICAL/HIGH/MEDIUM/LOW |
| SonarQube | Blocker/Critical/Major/Minor/Info（Java 静态分析事实标准） |

**结论**：词表无行业共识（6 家 6 种，3-6 级不等）；显示层与机器层分离是通行做法。定案：显示层中文五级（🔴 阻断 / 🟡 严重 / 🟢 一般 / 💡 轻微 / 📚 说明），机器值 **severe / important / normal / minor**（对齐团队分级枚举；important 恰好两套词表同词同位）。

衍生采纳：**分级判定边界**（重定义 Important，Anthropic 降噪纪律）——🟡 仅限导致生产环境行为异常的逻辑错误，风格/命名/测试完备性降级（report-generation 硬性要求 15）。

未采纳的启发（记录在案）：Pre-existing 标记（我们"上下文只读不报"更克制）；Why this was flagged 折叠推理（提问式/验证线索已部分覆盖）。

## 4. 设计边界（明确不做）

- **报告正文不减配**——可点击引用代码块、修复建议对照、问题速览表是核心 UX
- **清单不碎片化**——一份清单在其载入条件下都会被用到，拆文件只增加调用数不减总量
- **状态文件不加读放行条件**——已有容量上限与老化规则（lessons 软上限 80 行 / log 软上限 200 行 + 30 天老化）+ 每轮一次读取
- **不做 openspec 式归档目录**——耐久知识已萃取 lessons/rules，git 历史与聊天历史兜底，归档目录只是只写不读的第四存储位
- **不做 report.md 归档**——完整报告在聊天历史中，台账承载恢复上下文所需字段
- **不自动升级级别**——提醒徽标（≥3 轮未决）只记数；级别反映问题本身危害，升级是人的决策
- **不拆独立多轮 skill**——多轮是同一任务的记忆扩展，状态必须由 review 本体读写，拆分必然双头
- **分级词表不迁行业词表**——调研 6 家主流无统一标准（见 §3）；机器值对齐团队分级枚举，显示层保持中文

## 5. 降噪纪律（源自 Anthropic REVIEW.md 模式）

- **重定义 Important——已采纳**：报告硬性要求定义分级判定边界——🟡 严重仅限会导致生产环境行为异常的逻辑错误，风格/命名/测试完备性等一律降级；项目可在规约文件（rules/*.md）重定义
- **capping nits——暂不采纳，记录在案**：Anthropic 建议限制低级别发现数量；若 🟢/💡 噪音显著（经验判据：合计 >8 条且连续多轮），再考虑数量上限

## 7. 演进注意

- **改 spec 的同步链路**：一次设计决策通常波及 SKILL.md（工作流/常见错误）、review-state.md（状态语义）、report-generation.md（呈现）、subagent-dispatch.md（派发/执行）、README（用户可见）——改完全文搜旧表述确认无残留
- **并行会话交叉写台账**：会话内轮次用陈旧上下文（@command 才重载 skill）；写回前强制重读 review.md 已入规范，但并行会话仍可能写出旧格式——发现偏差按最新规范校正，等会话收尾再整理
- **验证方法**：机制问题优先查会话历史原始 JSON（`CodeBuddyExtension/Data/<uuid>/JetBrains/<uuid>/history/<dir>/messages/*.json`），用户粘贴的渲染文本会丢失 fence/格式信息，不可作为判定依据；用 node 临时脚本提取（PowerShell 对 node -e 内联正则会转义破坏，必须走脚本文件，放 `.aicoder/` 用完删）
- **报告渲染前抽查**：子代理返回的发现需抽查 1-2 条逐字代码与文件一致
- **晋升写入的两查**：同义去重（项目 rules + 用户级 rules + 内置清单）与口径冲突检查，见 review-state.md 第六节
